      Sahm Bank, its customers and policies are fictional. No real money moves. Personal data is masked before any model sees it. github.com/Zuhdiemara/wakeel

      How Wakeel works

      The model proposes. Code checks. A person approves.

      1 · The model proposes

      A LangGraph supervisor routes the case. A policy agent answers from the bank's policy with citations. An operations agent calls tools to look at the customer's transactions, and can only propose a refund.

      2 · Code checks

      Inside the tools: a real duplicate, within 60 days, under 5,000 SAR, and only the signed-in customer's own transactions. It never guesses between merchants. Messages are screened for prompt injection, and personal data is masked.

      3 · A person approves

      The graph pauses for a bank employee. Two different people must approve 1,000 SAR or more. The refund carries an idempotency key, so it can never be paid twice, and every action goes into a hash-chained audit trail.

      The graph

      customer message
  → intake        mask personal data · screen for attacks · detect language
  → supervisor    what does the customer need?  (model, rules as fallback)
  → policy agent  hybrid search over the policy → answer with citations
  → operations    tools: list_transactions · find_duplicates · search_policy
                         ask_customer · propose_refund
  → ask customer  pauses if it isn't clear which charge
  → approval      pauses for one or two bank employees
  → refund        ledger call with an idempotency key
  → reply         numbers checked against the facts
  ↘ to a person   attacks, stolen cards, anything it shouldn't decide

      Built with

      • Agents: LangGraph, tool calling, interrupt and resume, PostgreSQL checkpoints
      • Retrieval: Arabic-aware keyword search and Gemini embeddings, fused and reranked, with citations
      • Models: a chain of 7 free models (Gemini, Groq); rules keep working if all of them fail
      • Safety: injection patterns and Prompt Guard, PII masking, an output guard, a token budget
      • Production: FastAPI, JWT roles, job queue and workers, Docker, Kubernetes, OpenTelemetry, Prometheus
      • Evaluations in CI: 16/16 decisions on a live model with 0 unsafe refunds; 169 cases/s under load
